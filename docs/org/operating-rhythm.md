# 运营节奏

时间按香港时间（Asia/Hong_Kong，UTC+8），创始人 2026-10-18 确认。
已开通的定时任务：Scout 每日简报（每天 07:59）、Chief 每日站会（每天 08:57）。比整点提前几分钟触发，是为了避开整点的排队高峰。

| 频率 | 时间 | 谁 | 产出 | 位置 |
|---|---|---|---|---|
| 每天 | 08:00 | Scout | 情报简报：5–10 条 AI 软硬件热点 + 与我们项目的关系 + 1 个值得讨论的议题 | `ops/briefs/` |
| 每天 | 09:00 | Chief | 站会摘要：各项目昨日提交、未提交改动、阻塞、今日重点、临近节点 | `ops/standups/` |
| 每次 PR | 随时 | Probe | 测试与审查结论：通过 / 不通过 + 原因 | PR 评论 + `ops/quality/` |
| 每周五 | 17:00 | Probe | 代码库体检：依赖漏洞、密钥、体积、未提交改动、测试覆盖 | `ops/quality/` |
| 每周一 | 09:30 | Chief | 周复盘：上周完成、偏差、风险、本周 3 件最重要的事 | `ops/reviews/` |
| 每月 1 日 | 10:00 | Ledger | 经营月报：成本（API、算力、订阅）、预算余额、营销实验结果 | `ops/business/` |
| 随时 | — | Scout | 和创始人讨论想法 → 创意卡 | `ops/ideas/` |

## 监督机制（Chief）
1. 每份产出按模板检查：有没有来源、有没有结论、有没有下一步、有没有负责人和日期。
2. 不合格的打回给原岗位，并在站会摘要里记一笔。
3. 连续两次打回，或者节点逾期超过 3 天，在周复盘里升级给创始人。

## 自动化方式
- 每日和每周的岗位任务用 Claude Code 定时任务触发，每次触发时新开一个会话，加载本仓库和相关项目仓库。
- 只有推到 GitHub 的项目仓库才能被每日巡检；只在本地的项目，要在本地会话（Remote Control）里检查。
